# マッチングルール

## 基本思想

求人の意味に沿ったタグ候補を安定して抽出する。誤爆コストが高い項目では保守的に判定する。

## 前処理

最低限、Unicode NFKC、Latin文字の大小統一、前後空白整理を行う。過度な記号削除は避ける。

## match_policy

### normal
canonical / strict aliasを通常判定する。除外語と具体表現の優先順位を併用する。

### strict_only
canonical単独では確定せず、より具体的なstrict表現を要求する。現時点では高優先度レビューで一括採用していない。

### context
単語だけでは関係性が確定できない場合。現行では「採用」「介護」に加え、就業場所の高優先度60タグをcontext化。

就業場所例:
- `病院へ配送` ≠ 勤務地が病院
- `学校向け営業` ≠ 勤務地が学校
- `工場へ納品` ≠ 勤務地が工場

### pattern
数値・形式・閾値で判断する。

現行:
- 年間休日120日以上
- 残業月平均20時間以上
- 残業月平均20時間以内
- 固定給25万円以上
- 固定給35万円以上

固定給は「固定給」の明示を必須とし、月給・基本給・月収から推測しない。

### token_exact
短い英数字タグ向けの正式policy。

raw substring一致は禁止し、英数字のトークン境界で判定する。

例:
- `JavaScript` から `Java` を付与しない
- `GitHub` から `Git` を付与しない
- `Google...` から `Go` を付与しない
- `SCSS` から `CSS` を付与しない

## 除外語

除外語は文書全体を抑止するのではなく、誤爆する出現箇所を局所的に抑止する。

例:
- `接客なし` 内の「接客」は抑止
- `英語力不要` 内の「英語」は抑止
- `長期休暇` 内の「長期」は抑止
- `保育園` 内の「保育」は抑止
- 同じ文書の別箇所に `保育業務` があれば、その出現は別に判定可能

## 高優先度レビュー結果

133件を精査。

- 116件採用
  - 就業場所context: 60
  - token_exact: 56
- 17件は提案policyを見送り
  - 深夜 / 長期 / 英語: normal維持＋除外語
  - 看護 / 臨床 / 調理 / 保育 / 指導 / 工事 / 製造 / 財務 / 事務 / 接客 / 運転 / 人事 / 労務 / 清掃:
    strict_only一括化を見送り、normal維持＋局所除外語または具体表現優先

## canonical包含

より具体的な表現・否定表現を先に評価する。単純な最短substring優先は禁止。

## 判定結果

検証可能性のため、可能なら以下を残す。

- tag_code
- canonical
- hit_text
- hit_source
- decision: matched / review / suppressed
- reason
- surrounding_text
